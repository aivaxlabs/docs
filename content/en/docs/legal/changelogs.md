# Changelogs

Technical changes that affect AIVAX products, services, or the public API. Dates identify when entries were added or updated, not confirmed production rollout dates. Each item identifies the affected product or service; maintenance with no user-facing effect is omitted.

This page lists the changes from the last 14 days. Older entries are kept in the [changelog archive](https://github.com/aivaxlabs/docs/blob/master/archive/changelogs.md).

## Monday, November 9th, 2026

Fixes:

- **Language models — Failing providers are retried and avoided.** When a provider fails before it sends the first response token, including errors reported inside a streaming response, the request is now retried on another eligible provider instead of returning `Provider returned error`. Providers that keep failing are ranked lower by every routing preference and are temporarily removed from routing when they fail repeatedly. Requests limited by `allowed_providers` to a single unavailable provider can still fail; add `"*"` as the last item to allow a fallback. See [Routing setup](/docs/inference/routing/setup-routing.md).

## Sunday, November 8th, 2026

Changes:

- **Dashboard — Cached input share on Conversations.** The **Conversations** list has a new **Cached %** column showing how much of each conversation's input was served from the prompt cache. For conversations with more than 1K input tokens, the value is green above 95%, yellow above 90%, and shows a warning below that. A dash means no cached input was reported, which usually means the model or provider doesn't support prompt caching. `GET /api/v1/conversations` now also returns `cachedInputTokenCount`.
- **Dashboard — BYOK usage in Analytics.** **Usage per model** in **Analytics** now includes models used through AI gateways with your own provider key (BYOK). BYOK cost is an estimate based on the catalog price of the matching AIVAX model and is never charged; BYOK models with no catalog match show their tokens with no cost. The new **Effective usage** column shows the amount actually charged, and models used both ways show the AIVAX share of their tokens on hover. Past BYOK usage is estimated from stored conversations, so it only covers conversations that were kept. Balance, period spend, invoices, and monthly reports are unchanged.

## Saturday, November 7th, 2026

Changes:

- **Language models — Higher prices on Grand Anak routes.** Requests served by the `grand-anak-<route>` special providers now cost twice the previous token rates for input, cached input, and output. Other providers are not affected. Check current rates in `GET /api/v1/information/models.json`, and remove these tags from `allowed_providers` or use the `Balanced` preference to keep requests off special providers. See [Special providers](/docs/inference/routing/special-providers.md).

## Friday, November 6th, 2026

Breaking changes:

- **Account — Lower Pro and Max limits.** Pro and Max now have lower rate limits, storage, retention, and daily allowances. Max has fixed limits where it previously had none, a 10 GB storage quota with excess at $0.30/GB/month, 14-day conversation retention, and a 1.02x inference commission multiplier. Pro integrated model requests are 150/min and Pro search history is kept for 3 days. Review the new values in [Plans and limits](/docs/limits.md) and pace requests that could now return `429 Too Many Requests`.
- **Language models — Special provider routes renamed.** Each special provider route now has its own name and routing tag, such as `Grand Anak (Cyan Route)` with the tag `grand-anak-cyan`. The previous tags `grand-anak`, `grand-anak-flex`, and `grand-anak-route-<n>` no longer match any provider. If `allowed_providers`, an AI gateway's **Allowed providers**, or a `#tag` model suffix lists one of them, replace it with a current tag from `GET /api/v1/information/models.json`. See [Special providers](/docs/inference/routing/special-providers.md).

Fixes:

- **RAG — Collection tags update immediately.** The tags returned in collection details now reflect added, edited, and deleted documents right after the change, instead of possibly showing an earlier list for a few minutes.

Changes:

- **Models — LFM3-1.7B and DeepSeek V4.1 Flash 1017 abliterated.** Adds `@liquid/lfm-3-1.7b`, a compact reasoning model with tool calling and structured output, and `@deepseek/deepseek-v4.1-flash-1017-abliterated`, an uncensored variant of DeepSeek V4.1 Flash 1017 with tool calling and image input.
- **Dashboard — Avi Assistant conversations are not stored.** Conversations with the Avi Assistant in the dashboard no longer appear on the **Conversations** page. Usage and billing records are still created.
- **Account — Ultimate plan.** A new Ultimate plan is available at $199 per month. It keeps the limits previously offered by Max: no plan limit on integrated model requests, BYOK requests, or new Agentic Test runs, 20 GB of storage, 30-day retention, a 1.00x inference commission multiplier, and dedicated support. `GET /api/v1/information/plans.json` now also returns Ultimate. See [Plans and limits](/docs/limits.md) and [subscription pricing](https://aivax.net/pricing).
- **Docs — Plan limits on one page.** Every per-plan limit, including RAG, data processing, speech, built-in tools, Batch, and Agentic Tests, is now listed in [Plans and limits](/docs/limits.md#product-limits). Product pages link to it instead of repeating the values. The page also gives approximate PU and token sizes for common content, such as scanned PDFs, web pages, and RAG queries; see [Estimating PUs and tokens](/docs/limits.md#estimating-pus-and-tokens).
- **Dashboard — Plan comparison with Ultimate.** The **Plan** page in **My account** compares Free, Pro, Max, and Ultimate side by side, with list prices loaded from the public plan list.
- **Dashboard — Faster switching between saved accounts.** Switching to a saved account reuses its active console session when it is still valid, so the console no longer signs in again or asks for a two-factor code in that case. When the session has expired, the regular sign-in runs.
- **Docs — Inference pipeline pages.** The Inference section has new pages for [Processing pipeline](/docs/inference/chat-completions/processing-pipeline.md), with the order in which gateway steps run and how they affect each other, [Moderation](/docs/inference/chat-completions/moderation.md), [Context truncation](/docs/inference/chat-completions/context-truncation.md), and [Function interpreter](/docs/inference/chat-completions/function-interpreter.md). The previous standalone Processing pipeline page now redirects to the new one. The function interpreter (`knownToolHandlerName`) is now documented as deprecated; use a model with native tool calling instead.
- **Dashboard — Warning before discarding unsaved edits.** Editors for AI gateways, chat clients and their integrations, skills, Agentic Tests, Batch workflows, documents, and collection settings now ask for confirmation before you leave the page with unsaved changes, including through the browser back button, a reload, or closing the tab. The same applies when a dialog with a text or code field has been edited and is still open. Saving the page, or confirming or closing the dialog, clears the warning.
- **Dashboard — Clearer two-factor code fields.** The six code fields in the two-factor dialog are larger, show a placeholder dot in each empty field, highlight filled fields, and are centered in the dialog. The code is submitted as soon as all six digits are typed or pasted, and pressing Enter also confirms it.
- **Dashboard — Budget model for AI-assisted edits.** The panel for editing content with AI now preselects `@model-router/openai:budget`, and the panel is wider so all of its options fit. You can still choose another model before requesting the edit.

## Wednesday, November 4th, 2026

Breaking changes:

- **Inference — Chat completion IDs use the `aivx_` format.** In `/v1/chat/completions`, the response `id` and the `id` of every streamed chunk, including tool and error chunks, are now the assistant message ID in the `aivx_` format, instead of a UUID or a `chatcmpl-` value. Every chunk of a response shares the same ID. Tool call IDs are also longer. Update clients that validate the `chatcmpl-` prefix or expect a different ID per chunk.

Fixes:

- **Conversations — Conversation tokens are scoped to the account.** Two accounts that sent the same `idempotency_key` or `conversation_token` could update the same stored conversation record. Each account now keeps its own record for the same token. No action is required.

Changes:

- **Inference — Session reuse with `conversation_token`.** `/v1/chat/completions` accepts `conversation_token`. When the same token is sent in every request of a conversation, AIVAX restores the calls and results of server-side tools from earlier turns before the model runs, including turns that ended with a text-only answer. Responses return `conversation_token` at the root (in the last chunk when streaming) and the assistant message ID in `id` and `choices[].message.id` (in every chunk `id` when streaming). When no token is sent, AIVAX generates and returns one. `idempotency_key` remains a deprecated alias; sending both with different values returns `400 Bad Request`. See [Session reuse](/docs/inference/chat-completions/session-reuse.md).
- **Dashboard — Usage per model and per provider in Analytics.** On the **Analytics** page, the **Usage per model** table now shows one row per model with **Input tokens**, **Cached tokens**, **Output tokens** and **Total usage**, instead of one row per SKU. A new **Usage per provider** tab shows each provider with its top model by cost, token volume and total usage.
- **Generations — Inline reference images.** `POST /api/v1/generations/images` accepts `data:` URIs in `referenceImages` — `image/png`, `image/jpeg`, `image/webp` or `image/gif` with base64 data, up to 8 MB each — alongside HTTP(S) URLs. Invalid data URIs return `400 Bad Request`. See [Image generation](/docs/generations/images.md).

## Tuesday, November 3rd, 2026

Breaking changes:

- **Models — `is_deprecated` now means old or deprecated.** In `GET /v1/models` and `GET /api/v1/models`, `_details.provider_model.is_deprecated` was inverted: models released in the last 12 months were reported as deprecated, and older models were reported as current. It is now `true` only when the model is flagged as deprecated or its release date is more than 12 months before the current day. Models with no release date are not marked deprecated by age. Clients that hid or selected models from the previous value should invert that check. See [Deprecated models](/docs/inference/routing/setup-routing.md#deprecated-models).

Fixes:

- **API — Malformed resource identifiers return 400.** A path identifier that cannot be read, such as an incomplete ID on an AI Gateway or another resource route, now returns `400 Bad Request` instead of `500 Internal Server Error`. Treat that response as an invalid request and do not retry it as a server failure. See [Troubleshoot requests](/docs/inference/chat-completions/troubleshooting.md).
- **API — Browser clients can read request and cost headers.** Cross-origin responses now expose `X-Request-ID` and `Consumed-Credits`, so browser JavaScript can read the request identifier and the request cost when those headers are present. See [Request cost header](/docs/pricing.md#request-cost-header).
- **RAG — Indexing no longer fails when long documents are embedded together.** Indexing a collection no longer fails only because several long documents were embedded in one request. Split very large documents before import when you need precise retrieval; see [Document size](/docs/rag/documents.md#document-size).
- **Dashboard — OAuth authorization page no longer stuck loading.** When an application sends you to the console to request access, the page now shows the application name, the reason, the requested permissions and the **Authorize** and **Deny** buttons, instead of staying on "Loading the authorization request...". Invalid or expired requests show their error message again. See [OAuth](/docs/oauth.md).
- **Dashboard — Two-factor code prompt no longer stuck loading.** When signing in or switching to a saved account with two-factor authentication, the authentication code dialog shows the code fields instead of staying on "Getting things ready...".
- **RAG — JSONL imports with `insert-mode=sync` no longer time out in large collections.** After `END`, the **Index Documents (JSONL WebSocket)** endpoint could fail with an execution time error while removing documents absent from the stream, leaving those documents in the collection. Sync imports now finish in large collections, and imports with many lines complete faster. The multipart **Index Documents (JSONL)** endpoint also benefits for sync removals. A document changed by another request while a sync import is running is no longer removed by that import. If a previous sync import failed this way, send it again: unchanged documents are skipped and only the removal runs. Error messages now report the exact line that failed.

Changes:

- **Account — Pro and Max list prices.** The public Pro subscription is $19 per month, down from $39. Max is $99 per month, down from $399. These are list prices, not a negotiated account price. See [subscription pricing](https://aivax.net/pricing) and [Plan list prices](/docs/pricing.md#plan-list-prices).
- **Account — Public plan list prices.** `GET /api/v1/information/plans.json` returns the Free, Pro, and Max list prices without authentication. Each entry has `plan` and `monthlyPrice` in USD. Free is `0`. It does not return negotiated prices. See [Plan list prices](/docs/pricing.md#plan-list-prices).
- **Models — GLM-5.3-FlashX-Legal and Particle 1.** Adds `@z-ai/glm-5.3-flashx-legal` and `@particle-ai/particle-1` as selectable text models, billed per provider at published token rates. Existing account and plan adjustments still apply. Existing model identifiers remain unchanged.
- **RAG — Document text counts as UTF-8 bytes.** Text stored in a collection now counts toward the storage quota as UTF-8 bytes. Text that uses only basic Latin characters is unchanged. Text with accents or other non-Latin characters can use more of the quota than it did before. Other stored data is counted as before. See [Account limits](/docs/limits.md#account-limits).
- **Analytics — Printable monthly usage statement.** The **Monthly Reports** tab now produces a compact black-and-white document designed for printing and PDF export, showing the account name. Totals appear as a statement with a short description of each charge: **Inference**, **RAG** and **Services**, adding up to **Total billed**. The **Models used** table now lists input tokens, cached tokens, the cached share of the input, and output tokens for each model. Select **Include BRL values** to add a Brazilian real column beside each US dollar amount, converted at the exchange rate when the report is generated. Amounts in the report are shown with two decimal places. Through the API, `GET /api/v1/information/usage/monthly-report` returns the new `accountName` and `usdBrlRate` fields and per-model `inputTokens`, `cachedTokens` and `outputTokens`, and accepts `includeBrl=true`.
- **Dashboard — Simpler OAuth authorization page.** When an application requests access to your account, the console now shows a single centered card with the application name, the reason, the list of what it will be able to do, the access duration, and the **Authorize** and **Deny** buttons. The signed-in account is shown below the card, with a **Switch account** link that returns to the same request after signing in. See [OAuth](/docs/oauth.md).
- **Account — Step-by-step authenticator setup.** Adding an authenticator in the **Security** tab's two-factor authentication dialog now goes through separate steps. The first step shows the QR code and the secret in **QR code** and **Secret** tabs, with the reminder to save the secret. **Continue** opens the name and six-digit code fields. When the account already has an authenticator, a following step asks for a code from a current one. A confirmation step ends the setup. Invalid codes are shown inside the dialog, and **Back** returns to the previous step without clearing what was typed.

## Monday, November 2nd, 2026

Breaking changes:

- **API keys — Permissions by key type.** Each API key type now grants a fixed set of permissions, and routes that need a permission the key does not have return `403 Forbidden`, with the missing permissions in the error message. Private keys (`sk-aiv-acc`) can no longer list, create, or delete API keys, roll the account salt, manage authenticators, or reset the login key; use the dashboard instead. Public keys (`pk-aiv-`) can now call every `/api/v1/generations/*` endpoint, including classification, decisions, extraction, reranking, segmentation, summarization and translation. Public keys still cannot read or change account resources, open voice sessions, or use web search and fetch. See [Authentication](/docs/authentication.md).

Fixes:

- **Dashboard and website — Image model previews are back.** The image model picker on the **Generations** page and the image model catalog on the website show the model preview images again. They had stopped loading after image models moved to `@provider/model` names.
- **Dashboard — Readable capability icons in the light theme.** On the **Models** page, capability icons are now white on their colored circle in the light theme, instead of dark and hard to see.
- **RAG — Faster metadata filters in large collections.** [Document filters](/docs/rag/document-filters.md) with `metadata.<key>` conditions, such as `metadata.path startswith "docs/"`, no longer read the metadata of every document in the collection, so they are much less likely to exceed the execution time limit in large collections. This applies to collection queries, document browsing, memory search and the Collections MCP. Filter syntax and results are unchanged.

Changes:

- **Authentication — OAuth authorization for third-party applications.** Applications can request access to an account without asking for an API key. `POST /api/v1/auth/oauth` creates an authorization request with the application name, a reason, the requested permissions and a return URL, and returns the console address where the account holder approves it. The request expires in one hour. After signing in, the account holder reviews the request, chooses a duration of 1 day, 7 days, 90 days or 1 year, and is redirected back with an `access_token` (`sk-aiv-apk`) that has only the approved permissions. No refresh token is issued, and the API key management permission cannot be requested. Every application key can call `GET /api/v1/accounts`. **My account** has a new **Authorized applications** tab to list and revoke them. See [OAuth](/docs/oauth.md).
- **Image generation — Size, format, quality and per-image results.** `POST /api/v1/generations/images` accepts optional `size` (`"1024x1024"` or `{ "width": 1024, "height": 1024 }`, 64 to 4096 pixels per side), `format` (`png`, `jpeg` or `webp`) and `quality` (1 to 100, for `jpeg` and `webp`). Each prompt group keeps `images` and adds `outputs`, with the `url`, `cost` and `error` of every requested image, plus the group `cost`. Failed images have a `null` URL and are not charged. The `generate_image` tool of the [Media generation MCP](/docs/mcp-utilities/media-generation-mcp.md) accepts the same options and reports each image's cost or error, and `aivax generate image` adds `--size`, `--format` and `--quality`. See [Image generation](/docs/generations/images.md).
- **Dashboard — Richer image, speech, reranking and decision model catalogs.** On the **Models** page, the **Image models**, **Speech-to-text models**, **Text-to-speech models**, **Reranking models** and **Decision models** tabs show model cards like the **Text models** tab instead of a table. Image model cards show a sample image generated by that model. Each card shows the provider, the model name with a copy button, the description, the release date and the prices by unit, such as per output image, per reference image, per minute, per 1,000 characters or per 1M tokens. When available, it also shows decision model aliases, context size, maximum documents or images per request, supported audio formats, and capabilities such as image editing, mature content, yes/no, choice, score and image input. Badges mark default models, models included in subscriptions, rerankers that can only be used after RAG retrieval, and deprecated models. Each tab has a model search, and clicking the provider name filters by it. The actions menu adds **Model source** when the model has a published source.

## Friday, October 30th, 2026

Changes:

- **AI Gateways — Moderation mode.** AI gateway parameters accept `moderationParameters.mode`, with `LayeredGuardrail` (the default and previous behavior) and `SelfAssessment`. `LayeredGuardrail` analyzes the conversation's input text with an independent safeguard model before the main model and blocks flagged conversations. `SelfAssessment` runs no separate moderation call, so there is no moderation analysis charge: the main model receives moderation instructions built from the same category sensitivity levels and additional rules, plus an internal refusal tool, and ends the inference with a refusal when the latest request reaches an enabled category's boundary. It requires a model that supports tool calling and trades lower latency and cost for judgment that is not independent from the main model. The AI gateway editor's Content Moderation section includes a **Moderation mode** selector, and the gateway pipeline summary shows the active mode when moderation is enabled. See [Moderation](/docs/inference/chat-completions/moderation.md).
- **Dashboard — Agent setup prompt options.** The home page **Copy Prompt** button opens a menu with two setup prompts for coding agents: **Agent MCP + Skills**, which configures the account management MCP and the AIVAX agent skills, and **Agent CLI**, which installs the [AIVAX CLI](/docs/cli.md) and links the account as a CLI profile. The `GET /api/v1/accounts/agent-setup-prompt` endpoint accepts an optional `type` query parameter (`mcp`, the default, or `cli`).
- **CLI — Log in with an API key.** `aivax auth login --api-key <API_KEY>` links an account profile using an existing API key, without the account login key or authenticator code. See [CLI tool](/docs/cli.md#install).
- **Accounts — Get the authenticated account.** The new `GET /api/v1/accounts` endpoint returns the identifier, display name and e-mail of the account that owns the API key.
- **Conversations — Follow conversations in progress.** The new `GET /api/v1/conversations/management/live` Server-Sent Events stream sends the status of conversations being generated in the account: origin, model, elapsed time, partial token usage, and input and output previews. A finished conversation stays in the stream for 10 seconds with status `completed` and the stored `conversationId`, which is `null` when the conversation was not stored. `GET /api/v1/conversations/<id>` also accepts the live identifier and returns the current messages, and `GET /api/v1/conversations/<id>/sse` streams them until the conversation finishes. Only conversations that would be stored are tracked, so requests with conversation logging disabled do not appear. Server-side tool calls are only shown after the conversation is stored. On the **Conversations** page, conversations in progress appear above the stored list and the list refreshes when they finish; opening one follows it live and switches to the stored conversation when it is saved.

## Tuesday, October 27th, 2026

Breaking changes:

- **Language models — Models removed and router alias updated.** `@arcee-ai/trinity-large-thinking` is no longer in the model catalog; requests that name it are rejected. `@poolside/laguna-xs-2.1` and `@poolside/laguna-s-2.1` are removed; both were already deprecated and their provider endpoints expire on October 31, 2026. `@model-router/openai:mid` now selects `@openai/gpt-6.1-terra` instead of `@openai/gpt-6.1-sol`.

The replacements keep the same $0.02 per million input tokens price.

Changes:

- **RAG — Filter documents by reference.** Document filters accept the `reference` field with `=`, `!=`, `in`, `contains`, `startswith`, and `endswith`, for example `reference = "manual-v2"` to select every chunk of one source. Documents without a reference never match a positive condition on it, and match `reference != "..."`. Previously, `reference` was rejected as an unknown field. This applies wherever filters are accepted, including search, browse, and the Collections MCP tools. See [Document filters](/docs/rag/document-filters.md#fields).
- **MCP — Collections MCP browse and get document tools.** The Collections MCP now exposes two tools besides semantic search. The browse tool (`{collection_name}_browse_documents`, or `{collection_name}_list` with the `agent` naming convention) lists indexed documents with an optional document filter, sorting by creation, update, or indexing date, or name, and cursor pagination, and returns names, tags, and dates, with content only when requested. The get document tool (`{collection_name}_get_document`, or `{collection_name}_get`) reads one document by its exact name, optionally by line range, including documents still waiting to be indexed. Neither has search cost; both count toward the search rate limit. Clients that connect to the Collections MCP see two more tools; use `X-Mcp-Enabled-Tools` to hide them.
